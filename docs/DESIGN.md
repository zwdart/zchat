# zchat 设计说明

## 1. 目标

zchat 是一个不需要服务器的局域网聊天应用。它面向家庭、办公室、教室和临时协作场景：只要设备在同一个可互通的局域网里，打开应用就能发现彼此、聊天、发文件和共享目录。

设计目标是：

- **零配置**：默认情况下不需要账号、服务器或端口转发。
- **直接通信**：消息和文件只在两台设备之间传输。
- **桌面体验**：原生窗口、菜单、托盘、通知、拖放和快捷键。
- **可恢复**：资料、会话、未读和离线消息都保存在本机。
- **可发布**：支持 macOS、Windows、Linux 打包和签名自动更新。

非目标：

- 不提供端到端加密或身份认证。
- 不保证跨网段、跨 NAT 或公网可用。
- 不承载超大群聊或企业级权限系统。
- 不做音乐播放等与聊天无关的功能。

## 2. 总体结构

```
┌──────────────────────────────────────────────────────┐
│                    internal/app                      │
│  UI 视图 · 应用状态 · 菜单/托盘 · 设置 · 更新         │
└───────────────┬───────────────┬──────────────────────┘
                │               │
       ┌────────▼───────┐ ┌─────▼────────┐
       │ internal/lan   │ │ internal/share│
       │ 发现 + TCP 连接 │ │ HTTP 文件服务  │
       └────────┬───────┘ └─────┬────────┘
                │               │
       ┌────────▼───────┐ ┌─────▼────────┐
       │ internal/proto │ │ internal/store│
       │ 行式 JSON 帧   │ │ JSON 持久化   │
       └────────┬───────┘ └─────┬────────┘
                │               │
                └───────┬───────┘
                 ┌──────▼──────┐
                 │ internal/model│
                 │ 共享数据类型  │
                 └─────────────┘
```

| 包 | 职责 |
| --- | --- |
| `internal/model` | 资料、设备、会话、群组、消息、附件和状态枚举 |
| `internal/proto` | 帧信封、负载类型、读写与版本校验 |
| `internal/store` | 原子写入的 JSON 状态与消息存储 |
| `internal/netutil` | 局域网 IPv4 地址与广播地址 |
| `internal/lan` | UDP 发现、TCP 监听、连接注册、心跳与帧分发 |
| `internal/share` | 目录浏览、附件令牌、二维码 |
| `internal/app` | 应用状态、网络回调、业务逻辑和 MyGo UI |

依赖方向始终从 `app` 指向底层包；`model`、`proto` 和 `store` 不依赖 UI，便于测试。

## 3. 设备发现

发现使用两种互补的方式发送同一个小型 JSON 包：

1. **IPv4 组播**：`239.255.77.77:47823`，在每个支持组播的非回环接口上加入组。
2. **定向广播 + 受限广播**：按接口计算广播地址，并向 `255.255.255.255` 兜底发送。

这样在屏蔽组播的访客 Wi-Fi 或只允许广播的网络里仍有机会互相发现。

包内字段包括应用标记、协议版本、启动实例 ID、设备 ID、名称、签名、状态、版本、平台、TCP 端口和时间戳。**发现包不携带头像**，避免心跳过大；头像在 TCP 握手时交换一次。

节奏：

- 每 4 秒发送一次 `hello`。
- 启动和手动刷新时立即发送 `hello` 和 `probe`；收到 `probe` 的设备立即回应。
- 16 秒没有新包且没有 TCP 连接时标记离线。
- 退出时发送 `bye`。
- 隐身状态在发现包里写成离线，但仍保留 TCP 连接。

网络层的 `Node` 维护 `peers`（发现到的设备）和 `conns`（已建立的 TCP 连接）。发现和连接是分开的：即使广播被屏蔽，手动连接仍然可用；即使 TCP 断开，设备仍可能在发现列表里保留一段时间。

## 4. 连接与帧协议

TCP 连接建立后，双方先交换 `hello` 帧，携带自己的 `model.Peer`。如果两端同时拨号，用设备 ID 的字典序决定保留哪一条连接，避免重复连接。

每个帧是一行 JSON：

```json
{"v":1,"type":"chat","from":"u_...","data":{"message":{...}}}
```

`data` 为对应类型的负载。帧类型：

| 类型 | 方向 | 作用 |
| --- | --- | --- |
| `hello` | 双向 | 握手，交换设备资料 |
| `presence` | 广播 | 名称、签名、头像或状态变化 |
| `bye` | 主动 | 退出 |
| `ping` / `pong` | 双向 | 保活 |
| `chat` | 单播 | 一条聊天消息 |
| `ack` | 单播 | 确认收到消息 |
| `read` | 单播 | 已读到某个时间点 |
| `typing` | 单播 | 正在输入状态 |
| `recall` | 单播/群发 | 撤回消息 |
| `group` | 群发 | 邀请、更新、退出、解散 |

单帧上限 2 MiB。文件不会走 TCP 帧，而是通过 HTTP 附件地址发送，避免大文件占住消息通道。

## 5. 会话与消息路由

### 一对一

本机把对方设备 ID 直接作为会话 ID。这样：

- 发送时目标明确，不需要额外的会话映射服务。
- 收到对方消息时，无论对方使用什么本地会话 ID，都统一落到「发送者 ID」这个会话上。
- 设备改名或换 IP 不会改变会话。

### 群聊

群聊 ID 以 `g_` 开头，由创建者生成。群描述通过 `group` 帧传播，包含群名、群主、成员列表和时间。

- 每条群消息由发送者分别单播给每个成员，而不是依赖服务器转发。
- 成员收到后在自己的 `convs` 中查找群会话；找不到就丢弃，避免把群消息误显示成一对一消息。
- 邀请、改名、加人、移人、退出和解散都通过 `group` 帧同步。
- 群主解散群聊时通知所有成员删除本地群会话。

### 离线队列

`state.json` 中的 `outbox` 按设备 ID 保存尚未送达的 `chat`、`group` 和 `recall` 帧。对方重新连接时按顺序补发。队列上限 300 条，超出时丢弃最旧的。

`typing`、`read`、`ack` 等瞬时帧不进入离线队列。

## 6. 附件与文件共享

### 消息附件

发送文件时：

1. 如果 HTTP 服务未运行，先启动它。
2. 为文件生成随机令牌，登记到 `share.Server` 的 `transfers`。
3. 消息中写入附件名称、大小、MIME、宽高（图片）和 `http://<本机 IP>:<端口>/t/<令牌>/<文件名>`。
4. 接收方点击或自动下载时，通过该 URL 拉取文件，保存到缓存或下载目录。

`transfers.json` 持久化令牌，应用重启后旧消息里的链接仍然可用，前提是原文件还在。

**本地路径不会发给对方。** `model.File.Path` 只在本机有意义；发送前会复制一份消息并清空 `Path`，接收方也会清空它，避免把发送者的路径当成自己的缓存文件。

### 目录共享

`share.Server` 还是一个只读 HTTP 文件服务器：

- `/` 返回移动端友好的目录列表，支持搜索和面包屑返回。
- `/t/<token>/<name>` 返回消息附件。
- `/health` 返回 `zchat`，可用于探活。
- 共享目录为空时，服务仍可运行，附件链接仍然有效。
- 路径经过 `safeJoin` 校验，拒绝 `..` 和指向目录外的符号链接。

共享开启后，应用页面显示所有局域网 URL、二维码，并可把链接发送到当前会话。

## 7. 持久化

数据目录来自 `mygo.App.Path(mygo.PathUserData)`。

| 文件 | 内容 |
| --- | --- |
| `settings.json` | 外观、状态、通知、发现、端口、下载目录、共享目录 |
| `state.json` | 本机资料、会话、已知设备、离线队列 |
| `messages/<id>.json` | 单个会话的消息，按时间顺序 |
| `transfers.json` | 附件令牌到本地文件的映射 |
| `cache/` | 自动下载的图片和粘贴的临时图片 |

写入采用「临时文件 + rename」的原子方式。消息按会话拆分，避免一个繁忙会话反复重写全部历史。状态和消息都有 300ms 防抖，退出时强制落盘。

## 8. 应用状态与 UI

`app` 是唯一的应用状态持有者。网络 goroutine 不直接修改状态，而是通过 `post` 回到主线程；`post` 同时触发窗口重绘。

主要状态：

- `profile`：本机身份。
- `peers` / `convs` / `msgs`：设备、会话和消息。
- `outbox`：离线帧。
- `typing`：正在输入的人和过期时间。
- `transfers`：下载进度。
- `rows`：当前会话经过日期分组和搜索过滤后的消息行。

界面分为：

- **侧边栏**：资料、搜索、导航、会话列表、状态菜单。
- **聊天页**：会话头部、消息列表、搜索条、输入框。
- **发现页**：本机卡片、在线设备、手动 IP 连接。
- **共享页**：开关、共享目录、访问地址、二维码。
- **设置窗口**：资料、外观、通知、网络、文件、更新、关于。
- **对话框**：新建群聊、群信息、添加成员、备注、手动连接、确认操作。

消息列表使用 `ui.List` 的 `FollowEnd`：位于底部时自动跟随新消息，向上滚动后停止跟随。每条消息按 ID 作为列表 key，插入或删除时保持滚动位置。

## 9. 生命周期

`app.Run` 的顺序：

1. 单实例锁。
2. 注册更新插件、第二实例和通知点击回调。
3. `WhenReady` 后加载设置、数据目录、状态和消息。
4. 创建主窗口、菜单、网络节点和托盘。
5. 注册文件拖放、窗口聚焦和关闭行为。
6. 启动网络；如果设置了「启动时自动共享」，再启动 HTTP 服务。
7. 退出时保存设置和全部数据，停止网络、HTTP 服务和通知。

关闭窗口时，如果托盘可用且「关闭窗口时留在托盘」开启，就隐藏窗口而不是退出。macOS 始终保留菜单栏图标。

## 10. 更新

使用 MyGo 的 `updater/native` 插件：

- `mygo.json` 中配置 GitHub 仓库和更新公钥。
- 构建时用 `MYGO_UPDATER_PRIVATE_KEY` 签名更新包。
- 已安装的应用只接受对应私钥签名的更新。
- 检查频率为每天一次，也可以在设置里手动检查。

## 11. 安全与限制

- 协议没有加密，也没有身份认证；安全性依赖局域网本身可信。
- 文件共享是只读的，但任何能访问该 URL 的人都能下载共享目录里的文件。
- 附件令牌不可猜测，但会出现在消息记录中。
- 发现包和握手信息可以被局域网内其他设备看到。
- 不处理 NAT 穿透；跨网段需要手动连接或 VPN。
- 群聊成员列表由发送者维护，没有中心化的权限校验。

## 12. 测试策略

按照仓库的测试约定：

- **核心逻辑**：协议编解码、版本与大小限制、存储往返、路径逃逸、附件令牌、局域网连接注册、发现状态、消息行过滤。
- **不测展示细节**：不逐条断言界面文案或默认设置顺序。
- **时间可控**：需要日期的测试传入固定 `now`，不依赖运行时时钟。
- **竞态**：`go test -race ./internal/...` 应通过。
- **手工验证**：两台设备互相发现、群聊、文件、图片、共享目录、托盘和深色主题。
