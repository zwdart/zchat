## 1. 项目背景

zchat 当前已经支持图片消息、拖入窗口、粘贴剪贴板图片，以及 TCP/HTTP 附件传输，但用户要发送一张屏幕内容时，仍然需要借助系统截图工具或第三方软件，再回到聊天窗口粘贴或选择文件。这个流程在 Windows、macOS、Linux 上不一致，也无法在截图后直接标注、贴图或发送。

本项目在聊天页面内提供一套接近 Snipaste 的截图体验：

- 全局快捷键随时开始截图；
- 拖动选区、点击窗口、全屏、延时截图；
- 放大镜、取色、尺寸提示、窗口/屏幕边缘吸附；
- 矩形、椭圆、箭头、直线、画笔、荧光笔、文字、马赛克等标注；
- 复制、保存、贴图到屏幕、发送到当前会话；
- Windows、macOS、Linux 三个平台可用；
- 与现有聊天、附件和设置体系保持一致。

## 2. 项目目标

### 2.1 用户目标

1. 在任意应用前台时，按一次快捷键就能开始截图。
2. 截图后无需离开 zchat，就能完成常用标注并发送给聊天对象。
3. 截图结果可以钉在屏幕上，作为临时参考、对照或演示材料。
4. 在不同系统、不同缩放比例和多显示器环境下，选区与最终图片保持一致。
5. 操作方式接近 Snipaste，降低学习成本。

### 2.2 工程目标

1. 保持项目现有的纯 Go、无 cgo 构建方式。
2. 平台相关代码通过 build tag 隔离，核心几何、标注、导出逻辑可单元测试。
3. 不把截图内容上传到任何服务器；临时文件可清理。
4. 不破坏现有的图片发送、剪贴板粘贴、附件令牌和旧版本兼容逻辑。
5. 新增依赖尽量少，且必须为纯 Go 或系统库动态调用。

### 2.3 非目标

以下内容不作为首版必须完成的范围：

- 云端截图历史、跨设备同步；
- 视频录制、GIF 录制、滚动长截图；
- OCR 文字识别（可作为后续增强）；
- 截图内容自动打码、人脸识别；
- 远程桌面或跨网络截图；
- 完整的图像编辑器（图层、滤镜、调色、钢笔路径等）；
- 对所有 Wayland 合成器提供完全一致的前置选区体验；
- 支持 Windows 7、macOS 10.14 以下等过旧系统。

## 4. 用户场景

### 场景 A：把一段界面发给同事

1. 在聊天页点击输入框旁的截图按钮，或按 `F1`。
2. zchat 主窗口自动隐藏，屏幕变暗。
3. 拖动框选一个区域，右下角显示尺寸，放大镜显示像素颜色。
4. 用箭头和文字补充说明。
5. 点击“发送”或按 `Ctrl+Enter`。
6. zchat 恢复，图片作为当前会话的图片消息发送。

### 场景 B：临时对照资料

1. 在浏览器中按 `F1`。
2. 截图后点击“贴图”。
3. 图片窗口置顶停在屏幕角落，可拖动、缩放、调透明度。
4. 继续操作其他应用，需要时右键保存或关闭。

### 场景 C：只复制不发送

1. 按 `F1` 截图并标注。
2. 按 `Enter` 复制到剪贴板。
3. 切换到任意应用粘贴。

### 场景 D：Wayland 桌面

1. 按 `F1` 或桌面环境绑定的截图快捷键。
2. 系统门户弹出“允许截图”提示，用户确认。
3. 获得屏幕图像后，zchat 打开自己的标注窗口。
4. 标注完成后复制、保存或发送。

## 5. 成功指标

### 5.1 体验指标

| 指标 | 目标 |
| --- | --- |
| 按快捷键到出现选区界面 | 4K 屏幕 < 350ms |
| 选区完成到复制成功 | < 150ms |
| 标注拖拽刷新 | 60fps（常规 4K 截图） |
| 贴图窗口出现 | < 200ms |
| 取消/失败后恢复主窗口 | < 200ms |
| 首次使用权限引导 | 不需要查阅外部文档即可完成 |

### 5.2 质量指标

- 三个平台都能通过完整手工验收矩阵。
- 几何、标注、设置、文件名、导出逻辑有单元测试。
- `go test -race ./internal/...` 通过。
- `go vet ./...`、`go tool mygo vet` 通过。
- 不引入 cgo；`mygo build` 可继续跨平台打包。
- 截图失败不会导致主窗口丢失、应用退出或数据损坏。

### 5.3 隐私指标

- 截图只在内存和本机临时目录中存在，不上传。
- 退出应用后不保留未使用的临时截图（历史功能除外）。
- 日志不输出截图内容、像素、剪贴板内容或用户界面文本。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| macOS 屏幕录制权限拒绝或授权后需重启 | 无法截图 | 首次触发时检测权限；给出系统设置路径；提供“重试”；界面说明需重启旧系统应用 |
| macOS CoreGraphics 截屏 API 被标记废弃 | 未来系统失效 | 保留 `screencapture` 命令行回退；后续评估 ScreenCaptureKit 后端 |
| Wayland 不允许应用在截图前绘制全局 overlay | 无法做实时变暗/选区 | 采用“系统门户/工具先截全屏，zchat 再标注”的降级流程；明确能力提示 |
| Wayland 全局快捷键在旧桌面环境不可用 | 无法随时触发 | MyGo 已支持门户快捷键；失败时提示用桌面快捷键或命令触发 |
| Windows GDI 对 HDR/硬件加速窗口捕获异常 | 颜色偏差或黑屏 | 首版 GDI + 文档说明；后续增加 Windows Graphics Capture 后端 |
| 多显示器混合 DPI 坐标错误 | 选区偏移、图片裁剪错误 | 统一 DIP/物理像素模型；每显示器单独映射；混合 DPI 手工测试 |
| 4K/多屏截图内存占用高 | 卡顿或 OOM | 只截当前显示器；及时裁剪并释放原始帧；限制历史缓存 |
| overlay 无法获得焦点或置顶 | 键盘快捷键失效 | macOS 使用 Panel；Windows/Linux 使用无边框置顶窗口；启动后主动 Focus |
| 全局快捷键被其他应用占用 | 无法触发 | 注册失败时提示并允许修改；提供菜单/按钮/托盘入口 |
| 发送截图时主窗口未恢复 | 用户看不到发送结果 | 完成动作后统一恢复主窗口并打开对应会话 |
| 剪贴板写入失败（Linux 剪贴板所有者退出） | 复制不可用 | 捕获错误并提示；应用保持运行期间保留剪贴板；必要时提示重试 |
| 新增依赖影响构建 | 打包失败 | 优先纯 Go；依赖最小化；CI 覆盖三平台构建 |

## 11. 依赖与前置条件

- Go 1.27.3 或更高版本，与 `go.mod` 一致。
- MyGo v0.7.4：使用其窗口、原生 UI、快捷键、剪贴板、显示器信息和菜单能力。
- Windows：系统自带的 GDI/DWM/Win32 API，无需额外运行时。
- macOS：系统 CoreGraphics/AppKit；屏幕录制权限。
- Linux X11：X 服务器和常用 X11 库；优先使用纯 Go X 协议或动态调用。
- Linux Wayland：`xdg-desktop-portal`，或 `grim`/`gnome-screenshot`/`spectacle` 等回退工具。
- 新的 Go 依赖需经过评审，确保纯 Go、许可证兼容、可交叉编译。

## 13. 发布策略

1. 先在开发分支实现 Windows 主链路，内部验证。
2. 增加 macOS 与 Linux X11，完成手工矩阵。
3. Wayland 作为“编辑器模式”发布，并在说明中标注能力差异。
4. 先在设置中默认开启截图功能，但全局快捷键注册失败不阻塞应用启动。
5. 发布说明列出平台差异、权限要求、已知限制。
6. 若某平台截屏后端出现严重问题，可通过设置禁用该平台截图入口，不影响聊天主功能。

## 14. 待评审问题

1. 默认快捷键用 `F1` 还是 `CmdOrCtrl+Shift+A`？`F1` 更接近 Snipaste，但与部分系统/软件冲突。
2. 截图默认动作是“进入标注”还是“复制后进入贴图”？建议默认进入标注，复制为 Enter。
3. 截图保存目录用“图片/zchat”还是“下载/zchat/Screenshots”？
4. 贴图是否需要跨应用重启保留？建议首版不保留。
5. OCR 是否进入 P1？若进入，需要评估系统 OCR 与 tesseract 的差异。
6. 是否允许在 zchat 自己的贴图窗口上继续截图？建议默认允许（与系统截图一致），不额外隐藏贴图。
7. Wayland 下是否接受“先由系统截图，再进入 zchat 标注”的产品体验？需要产品确认。
